# 具体设计文档

## 1. 文档说明

- 项目名称：备忘秘书小程序
- 文档目的：将需求分析与概要设计细化为可直接指导编码、联调和测试的模块设计。
- 技术栈：微信原生小程序、Vant Weapp、微信云开发（云函数、云数据库、云存储、定时触发器、订阅消息）。
- 范围：覆盖 MVP 必做功能；用户统计保留扩展设计，手写功能不纳入本期。

## 2. 设计约定与边界

1. 用户身份以云函数运行环境取得的 `OPENID` 为准。前端传入的 `_openid` 不得作为权限判断依据。
2. `level` 表示时间管理四象限，数值越大，列表优先级越高：
   - `4`：重要且紧急；
   - `3`：重要但不紧急；
   - `2`：紧急但不重要；
   - `1`：不重要且不紧急。
   此定义将“象限”映射到现有 `level` 字段，不额外增加紧急程度字段。
3. 任务列表排序：置顶任务优先，其次 `level` 降序，再按 `ddl` 升序；最后按 `createTime` 降序作为稳定排序条件。随笔列表排序：置顶优先，其次 `createTime` 降序。
4. 用户可不启用提醒。若用户拒绝订阅授权，或未选择提醒时间，任务仍可保存，但不创建待发送提醒。
5. 每个任务最多发送一条提醒。发送接口明确成功后才标记为已发送；失败应记录日志，不得伪装成成功。微信平台是否实际展示消息仍受平台规则与用户设置影响。
6. “系统消息”在 MVP 中以用户反馈的管理员回复为主要来源。当前数据模型没有独立通用消息集合，因此本期不实现任意广播消息。
7. 管理员统计属于缓做项；本期仅保留模块边界，不要求实现统计页面或统计云函数。
8. 头像、昵称等微信用户资料与用户身份分离：`_openid` 用于身份识别；头像、昵称及其他资料由用户资料模块维护。不得假定仅凭登录就一定能获得所有资料字段。

## 3. 总体架构

```text
微信小程序页面
  ├─ 登录与全局状态
  ├─ 任务列表 / 任务编辑与详情
  ├─ 随笔列表 / 随笔编辑与详情
  ├─ 我的 / 基础资料 / 反馈 / 系统消息
  └─ 管理员 / 反馈管理（统计暂缓）
          │ wx.cloud.callFunction
          ▼
微信云函数
  ├─ login       身份识别与用户记录初始化
  ├─ task        任务 CRUD、置顶与提醒字段维护
  ├─ note        随笔 CRUD、置顶
  ├─ user        用户资料读写
  ├─ feedback    反馈提交、修改与查询
  ├─ admin       管理员校验、反馈列表与回复
  └─ sendReminder 定时扫描与订阅消息发送
          │
          ▼
云数据库：users / tasks / notes / admins / feedbacks
云存储：任务与随笔图片
微信订阅消息：任务提醒
```

前端负责表单交互、展示、图片选择和上传、订阅授权申请；云函数负责身份识别、权限校验、输入校验、业务规则与数据库操作。任何关键权限不得只在前端实现。

## 4. 数据库详细设计

### 4.1 `users` 用户集合

| 字段 | 类型 | 必填 | 规则/说明 |
|---|---|---:|---|
| `_openid` | string | 是 | 微信用户唯一标识；按该字段查询或更新用户记录 |
| `avatar` | string | 否 | 头像地址或云存储文件标识，按实际头像方案统一存储 |
| `nickname` | string | 否 | 昵称 |
| `gender` | string | 是 | 默认 `保密`；建议取 `男`、`女`、`保密` |
| `birthday` | string | 否 | 日期字符串，统一使用 `YYYY-MM-DD` |
| `address` | string | 否 | 用户自行填写的地域/地址信息 |
| `job` | string | 否 | 职业 |
| `createTime` | date | 是 | 首次创建时间，创建后不因资料编辑而覆盖 |

约束：登录时按云函数取得的 openid 查找用户；不存在则创建默认资料；存在则返回已有资料，不重置用户填写的字段。用户资料更新采用字段白名单，只允许修改资料字段。

### 4.2 `tasks` 任务集合

| 字段 | 类型 | 必填 | 规则/说明 |
|---|---|---:|---|
| `_id` | string | 系统生成 | 文档主键 |
| `_openid` | string | 是 | 所属用户，由云函数写入 |
| `name` | string | 是 | 去除首尾空格；空值使用 `无名` |
| `type` | string | 是 | 内置或自定义类型字符串 |
| `level` | number | 是 | 整数 `1`–`4`，对应四象限 |
| `ddl` | date | 是 | 截止时间，必须是有效日期 |
| `content` | string | 是 | 去除首尾空格后不得为空 |
| `images` | array | 是 | 云存储 `fileID` 数组，无图片时为空数组 |
| `top` | boolean | 是 | 默认 `false` |
| `remindAt` | date/null | 否 | 未启用提醒时为空；启用时必须是有效时间 |
| `reminded` | boolean | 是 | 默认 `false`；仅在发送接口确认成功后设为 `true` |
| `createTime` | date | 是 | 创建时由云函数写入，编辑时不变 |

校验规则：
- `name` 为空时使用默认值；`type` 为空时前端应要求选择或填写类型。
- `level` 必须是 1–4 的整数。
- `ddl` 和 `content` 必填；提醒时间不得晚于任务截止时间。提醒时间已过去时，前端应提示并要求重新选择或关闭提醒。
- 更新、删除、置顶前必须同时匹配任务 `_id` 与当前用户 openid。
- 编辑任务时，如果提醒时间发生变化，重置 `reminded=false`；如果关闭提醒，将 `remindAt` 清空并确保定时任务不会发送旧提醒。
- 删除任务后，该任务不得再被定时扫描发送。

### 4.3 `notes` 随笔集合

| 字段 | 类型 | 必填 | 规则/说明 |
|---|---|---:|---|
| `_id` | string | 系统生成 | 文档主键 |
| `_openid` | string | 是 | 所属用户，由云函数写入 |
| `title` | string | 是 | 去除首尾空格；空值使用 `无题` |
| `content` | string | 是 | 正文；提交前校验非空 |
| `images` | array | 是 | 云存储 `fileID` 数组，无图片时为空数组 |
| `top` | boolean | 是 | 默认 `false` |
| `createTime` | date | 是 | 创建时间，编辑时不变 |

约束：查询、更新、删除、置顶均需按 `_id` 与当前用户 openid 联合校验。编辑不改变创建时间；列表置顶优先，同置顶状态按创建时间倒序。

### 4.4 `admins` 管理员集合

| 字段 | 类型 | 必填 | 规则/说明 |
|---|---|---:|---|
| `_openid` | string | 是 | 被授权管理员的 openid |
| `name` | string | 否 | 管理员备注名 |

管理员身份通过后台预先维护的白名单确定，不提供普通用户自行申请或修改管理员身份的接口。每个管理员云函数操作都必须重新鉴权。

### 4.5 `feedbacks` 反馈集合

| 字段 | 类型 | 必填 | 规则/说明 |
|---|---|---:|---|
| `_id` | string | 系统生成 | 文档主键 |
| `_openid` | string | 是 | 提交用户，由云函数写入 |
| `content` | string | 是 | 反馈正文，去除首尾空格后不得为空 |
| `reply` | string | 否 | 管理员回复；未回复时为空字符串 |
| `repliedAt` | date/null | 否 | 回复时间；未回复时为空 |
| `createTime` | date | 是 | 提交时间 |

规则：
- 用户只能查看自己的反馈。
- 用户仅可修改尚未回复的反馈；回复后前端置灰，云函数仍须拒绝修改。
- 管理员只能通过 `admin` 云函数查看反馈与回复；回复操作要求管理员身份有效。
- 管理员回复时写入 `reply` 与 `repliedAt`。本期不支持回复后再次编辑或删除回复。

### 4.6 索引与查询建议

按实际云数据库控制台支持情况创建必要索引：
- `tasks`：`_openid`、`top`、`level`、`ddl`、`createTime` 的常用组合索引；
- `notes`：`_openid`、`top`、`createTime` 的常用组合索引；
- `feedbacks`：`_openid`、`createTime`；管理员反馈列表按 `createTime` 排序；
- `admins`：`_openid`；
- `users`：`_openid`。

组合索引应以真实查询条件为准，避免不必要的索引。列表数据量较大时采用分页，避免一次性读取全部记录。

## 5. 云函数接口设计

本节是前后端联调的接口契约。前端按本节传参，云函数按本节校验和返回；若实现时需要调整字段、类型或语义，应同步修改本文档，避免前后端各自约定。

### 5.1 通用约定

#### 5.1.1 调用方式与参数位置

普通业务接口通过 `wx.cloud.callFunction` 调用对应云函数。请求参数放在 `data` 中，业务参数直接作为 `data` 对象的字段，不再额外嵌套一层 `params`。

```javascript
const res = await wx.cloud.callFunction({
  name: "task",
  data: {
    action: "list",
    page: 1,
    pageSize: 20
  }
});

// 云函数业务响应在 res.result 中
const result = res.result;
```

除 `login` 外，具有多个操作的云函数使用 `action` 字段分派。云函数名、`action` 和字段名区分大小写，必须按本文档拼写。客户端不得提交或依赖 `_openid`、`createTime`、`reminded` 等服务端控制字段。

#### 5.1.2 统一响应结构

所有普通云函数均返回以下业务结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | `0` 表示成功；非 `0` 表示失败 |
| `message` | string | 简短、可供前端判断或展示的信息 |
| `data` | object / array / null | 成功时为结果数据；失败时为 `null` |

成功示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "task_xxx"
  }
}
```

失败示例：

```json
{
  "code": 400,
  "message": "level 必须为 1 到 4 的整数",
  "data": null
}
```

前端应先检查 `res.result` 是否存在，再判断 `res.result.code`。云函数调用本身发生网络或运行时异常时，可能无法取得上述业务结构，前端还必须使用 `try/catch` 处理调用异常。

#### 5.1.3 错误码

| `code` | 含义 | 典型场景 |
|---:|---|---|
| `0` | 成功 | 操作完成 |
| `400` | 参数错误 | 必填字段缺失、类型不正确、时间格式错误 |
| `401` | 未识别当前用户 | 云函数上下文中无法取得 `OPENID` |
| `403` | 无权限 | 非管理员调用管理操作，或记录不属于当前用户 |
| `404` | 记录不存在 | 指定的任务、随笔或反馈不存在 |
| `409` | 状态冲突 | 反馈已经回复，不能再修改 |
| `500` | 服务端错误 | 未预期异常、数据库操作失败、配置缺失 |

不应把数据库堆栈、密钥、完整内部异常直接返回给前端。详细错误写入云函数日志，并使用可定位问题的请求上下文辅助排查。

#### 5.1.4 日期、空值与分页

- **日期传输格式**：前端向云函数传递日期时使用 ISO 8601 字符串，例如 `2026-10-20T15:59:00.000Z`；响应中的日期也统一序列化为该格式。云数据库内部使用 `Date` 类型保存日期。前后端必须统一时区转换，页面显示时再按用户本地时区格式化。
- **日期字段**：`ddl` 是任务截止时间；`remindAt` 是提醒触发时间。未设置提醒时，`remindAt` 返回 `null`。
- **可选字段**：创建时未传入且有默认值的字段由服务端补齐；更新时未传入的字段保持原值。明确传入 `null` 仅在字段定义允许清空时生效。
- **分页参数**：`page` 从 `1` 开始，默认 `1`；`pageSize` 默认 `20`，允许范围 `1`–`100`。不传分页参数时，列表接口仍使用默认分页，避免一次读取全部数据。
- **分页返回值**：列表接口统一返回 `list`、`total`、`page`、`pageSize`、`hasMore`。`total` 是符合筛选条件的记录总数；`hasMore` 表示是否还有下一页。
- **身份与归属**：服务端通过云函数上下文取得 `OPENID`。即使请求中出现 `_openid`，也必须忽略；所有个人数据读写都以服务端取得的 openid 限定范围。
- **更新规则**：更新接口只接受明确列出的可编辑字段；不得将整个客户端对象直接写入数据库。

统一分页响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "pageSize": 20,
    "hasMore": false
  }
}
```

### 5.2 `login`：登录与用户初始化

此云函数不接受客户端传入的身份标识。身份来自云函数上下文中的 `OPENID`。

**请求**

```javascript
wx.cloud.callFunction({
  name: "login",
  data: {}
});
```

**处理规则**

1. 获取当前 `OPENID`；无法取得时返回 `401`。
2. 按 `_openid` 查询 `users`。
3. 若不存在，创建一条默认用户资料，并写入服务端生成的 `createTime`。
4. 若已存在，直接返回现有资料，不覆盖用户自行维护的字段。
5. 返回面向前端的用户资料对象；不返回其他用户的数据。

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "user": {
      "_openid": "openid_from_cloud_context",
      "avatar": "",
      "nickname": "",
      "gender": "保密",
      "birthday": "",
      "address": "",
      "job": "",
      "createTime": "2026-10-14T02:00:00.000Z"
    }
  }
}
```

`_openid` 在此响应中仅用于前端识别当前资料（如确有展示需要）；前端不得将其作为后续接口的权限凭据。若不需要展示或缓存该值，可以不向前端返回。

### 5.3 `task`：任务管理

所有操作均要求当前用户已被云函数识别。以下响应中的 `id` 对应云数据库记录的 `_id`；对外统一使用 `id`，数据库内部使用 `_id`。

#### 5.3.1 `list`：查询任务列表

**请求字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `action` | string | 是 | 固定为 `list` |
| `page` | number | 否 | 页码，从 `1` 开始，默认 `1` |
| `pageSize` | number | 否 | 每页条数，默认 `20`，范围 `1`–`100` |

**请求示例**

```json
{
  "action": "list",
  "page": 1,
  "pageSize": 20
}
```

**成功响应**

`data` 使用统一分页结构。`list` 中每项包含 `id`、`name`、`type`、`level`、`ddl`、`content`、`images`、`top`、`remindAt`、`reminded`、`createTime`。如列表页不需要正文或图片，可在实现中减少返回字段，但前后端需统一字段约定。

排序顺序：`top` 降序、`level` 降序、`ddl` 升序、`createTime` 降序。只查询当前用户的任务。

#### 5.3.2 `detail`：查询任务详情

**请求字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `action` | string | 是 | 固定为 `detail` |
| `id` | string | 是 | 任务 ID |

**请求示例**

```json
{
  "action": "detail",
  "id": "task_xxx"
}
```

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task": {
      "id": "task_xxx",
      "name": "完成课程作业",
      "type": "课程",
      "level": 3,
      "ddl": "2026-10-20T15:59:00.000Z",
      "content": "完成软件工程课程作业",
      "images": [],
      "top": false,
      "remindAt": null,
      "reminded": false,
      "createTime": "2026-10-14T02:00:00.000Z"
    }
  }
}
```

若记录不存在返回 `404`；若记录不属于当前用户，返回 `403` 或统一的不可访问错误，不得泄露该记录是否属于其他用户。

#### 5.3.3 `create`：创建任务

**请求字段**

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `action` | string | 是 | 固定为 `create` |
| `name` | string | 否 | 去除首尾空格；为空时使用 `无名` |
| `type` | string | 是 | 非空字符串 |
| `level` | number | 是 | 整数，范围 `1`–`4` |
| `ddl` | string | 是 | ISO 8601 日期时间，必须有效 |
| `content` | string | 是 | 去除首尾空格后不得为空 |
| `images` | string[] | 否 | 云存储 `fileID` 数组，默认 `[]` |
| `remindAt` | string / null | 否 | 提醒时间；未启用时传 `null` 或省略 |

客户端不得传入 `id`、`_id`、`_openid`、`top`、`reminded`、`createTime`。这些字段由服务端生成或初始化。

**请求示例**

```json
{
  "action": "create",
  "name": "完成课程作业",
  "type": "课程",
  "level": 3,
  "ddl": "2026-10-20T15:59:00.000Z",
  "content": "完成软件工程课程作业",
  "images": [],
  "remindAt": "2026-10-19T15:59:00.000Z"
}
```

**校验与处理**

1. 校验 `type`、`level`、`ddl`、`content`。
2. `name` 为空时使用 `无名`；`images` 未传时使用空数组。
3. `remindAt` 非空时必须是有效时间，且不得晚于 `ddl`；已过期的提醒时间拒绝保存。
4. 写入当前用户的 `_openid`、`top=false`、`reminded=false`、`createTime=当前服务端时间`。
5. 若未设置提醒，将 `remindAt` 保存为 `null`。

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task": {
      "id": "task_generated_id",
      "name": "完成课程作业",
      "type": "课程",
      "level": 3,
      "ddl": "2026-10-20T15:59:00.000Z",
      "content": "完成软件工程课程作业",
      "images": [],
      "top": false,
      "remindAt": "2026-10-19T15:59:00.000Z",
      "reminded": false,
      "createTime": "2026-10-14T02:00:00.000Z"
    }
  }
```

#### 5.3.4 `update`：修改任务

**请求字段**

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `action` | string | 是 | 固定为 `update` |
| `id` | string | 是 | 任务 ID |
| `name` | string | 否 | 允许修改；空字符串按 `无名` 处理 |
| `type` | string | 否 | 传入时必须非空 |
| `level` | number | 否 | 传入时必须为 `1`–`4` 的整数 |
| `ddl` | string | 否 | 传入时必须为有效 ISO 8601 日期时间 |
| `content` | string | 否 | 传入时不得为空 |
| `images` | string[] | 否 | 传入时必须是 `fileID` 数组 |
| `remindAt` | string / null | 否 | 传入 `null` 表示关闭提醒；传入时间表示设置/修改提醒 |

**请求示例：修改提醒时间与正文**

```json
{
  "action": "update",
  "id": "task_xxx",
  "content": "完成软件工程课程作业并检查格式",
  "remindAt": "2026-10-19T12:00:00.000Z"
}
```

**处理规则**

- 必须先按 `id` 与当前用户 openid 确认记录归属。
- 只更新请求中明确提供且在白名单内的字段；不允许修改 `_openid`、`createTime`、`top`、`reminded`。
- 更新后整体校验 `ddl` 与 `remindAt` 的关系，避免只更新其中一个字段时产生非法组合。
- `remindAt` 改变时重置 `reminded=false`；传入 `null` 时清空提醒时间并重置状态。定时扫描必须重新读取最新记录并确认提醒仍有效，不能只依赖旧扫描结果。
- 当前数据模型支持修改提醒时间后重新安排提醒，因此“最多一次”应理解为每个有效提醒配置最多成功发送一次，而不是同一任务从创建到删除永远只能发送一次。
- 返回更新后的任务对象。

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task": {
      "id": "task_xxx",
      "name": "完成课程作业",
      "type": "课程",
      "level": 3,
      "ddl": "2026-10-20T15:59:00.000Z",
      "content": "完成软件工程课程作业并检查格式",
      "images": [],
      "top": false,
      "remindAt": "2026-10-19T12:00:00.000Z",
      "reminded": false,
      "createTime": "2026-10-14T02:00:00.000Z"
    }
  }
}
```

### 5.8 `sendReminder`：定时任务提醒（内部接口）

`sendReminder` 由云开发定时触发器调用，不属于普通页面 CRUD 接口，不提供给前端按钮直接调用。其触发频率为每分钟一次。

**触发器输入**：无用户可控业务参数；执行时间与运行上下文由云平台提供。

**处理流程**

1. 获取当前服务端时间 `now`。
2. 分批查询 `remindAt <= now`、`remindAt` 非空且 `reminded=false` 的任务。
3. 对每条候选记录重新读取最新数据，确认任务仍存在、提醒未关闭、提醒时间仍到期，并确认接收用户及模板配置可用。
4. 通过可行的条件更新/锁机制防止多个触发实例同时处理同一任务；锁失败的实例跳过该记录。
5. 调用微信订阅消息发送接口，按已配置模板映射任务名称、截止时间等字段。
6. 仅在微信发送接口明确返回成功后，将 `reminded` 更新为 `true`；失败时记录任务 ID、错误码和时间，不得标记为成功。
7. 单条任务失败不应中断其余任务；设置单次扫描上限，避免超时。

**内部执行结果与日志**

该云函数不需要向前端返回业务数据。执行日志至少记录扫描数量、成功数量、失败数量及可排查的错误码；不得记录不必要的个人资料或密钥。

**提醒状态说明**

当前数据模型以 `remindAt` 与 `reminded` 表示提醒配置及发送结果。更改提醒时间会将 `reminded` 重置为 `false`，因此语义是“每个有效提醒配置最多成功发送一次”；修改提醒时间后可能再次发送。定时任务必须重新校验最新记录，防止用户关闭或更改提醒后仍按旧扫描结果发送。数据库更新与微信发送调用不是一个原子事务，系统只能尽量防止并发重复，不能承诺严格的恰好一次投递。

### 5.9 云存储上传接口边界

图片文件不通过 `task` 或 `note` 云函数上传。前端调用 `wx.cloud.uploadFile` 将图片上传到云存储，拿到 `fileID` 后，再将 `fileID` 数组传给 `task.create/update` 或 `note.create/update`。

建议使用可区分业务类型与用户的云存储路径，例如：

```text
task-images/{openid}/{timestamp}_{random}.jpg
note-images/{openid}/{timestamp}_{random}.jpg
```

路径只用于组织文件，不构成权限校验依据。上传完成后，业务云函数应校验 `images` 为数组且元素为字符串；如需更强的文件归属校验，应增加服务端文件归属校验策略。图片选择数量、单文件大小、允许格式等限制由前端和云存储配置共同执行，并在实际项目配置中固定具体数值。

### 5.10 接口实现与联调检查清单

- [ ] 云函数名称、`action` 名称、字段名与本文档一致。
- [ ] 成功与失败均使用统一响应结构；云函数运行异常由前端 `try/catch` 兜底。
- [ ] 所有个人数据操作均以服务端 `OPENID` 限定范围。
- [ ] 所有更新操作使用字段白名单，客户端不能覆盖身份、创建时间、置顶状态和提醒发送状态等服务端字段。
- [ ] 所有列表接口使用统一分页参数和返回结构。
- [ ] 日期字段统一采用 ISO 8601 字符串传输、数据库 `Date` 类型存储。
- [ ] 管理员每次执行管理操作都重新鉴权。
- [ ] 提醒关闭、修改、删除、并发触发和发送失败场景均已测试。
- [ ] 图片业务字段只保存云存储 `fileID`，不保存本地临时路径。
- [ ] 修改接口契约后，同步更新前端调用、云函数实现和测试用例。

## 6. 图片上传设计

1. 页面通过 `wx.chooseMedia` 选择图片。
2. 前端限制可选数量与大小，并给出上传进度/失败提示。
3. 通过 `wx.cloud.uploadFile` 上传至云存储，获取 `fileID`。

6. 上传失败时允许重试；数据库保存失败时提示用户，不应显示“保存成功”。

本期只实现图片，不扩展视频、附件或手写内容。

## 8. 关键业务流程

### 8.1 新建任务

1. 用户填写名称、类型、四象限等级、DDL、正文与图片。
2. 用户选择是否设置提醒；若设置，选择一个提醒时间。
3. 前端校验必填项与时间关系，并上传图片。
4. 若启用提醒，调用订阅消息授权 API；授权被拒绝时告知用户，允许继续保存不带提醒的任务。
5. 调用 `task.create`，服务端再次校验数据并写入。
6. 成功后返回列表或详情；失败保留表单内容并提示重试。

### 8.2 修改任务提醒

1. 用户修改提醒时间或关闭提醒。
2. 前端提交更新请求。
3. 云函数校验任务归属与时间规则。
4. 更新提醒字段；提醒时间改变时重置 `reminded=false`，关闭提醒时清空 `remindAt`。
5. 返回更新结果并刷新页面。

### 8.3 用户反馈与管理员回复

1. 用户提交反馈，云函数写入用户 openid 与提交时间。
2. 用户可修改尚未回复的反馈。
3. 管理员进入反馈管理页，云函数先校验白名单身份。
4. 管理员回复后写入回复内容与回复时间。
5. 用户刷新系统消息/反馈页面即可看到回复；该反馈变为不可编辑。

## 9. 异常处理

| 场景 | 处理方式 |
|---|---|
| 登录或云函数调用失败 | 展示可理解的错误提示，允许重试 |
| 表单字段缺失/格式错误 | 前后端均校验；以后端校验为准 |
| 记录不存在或不属于当前用户 | 返回统一的无权访问/记录不存在错误，不泄露其他用户数据 |
| 图片上传失败 | 显示失败项，允许重试，不保存失效的临时路径 |
| 订阅授权被拒绝 | 任务仍可保存，但不启用提醒 |
| 提醒时间非法或已过期 | 阻止设置该提醒并要求修改 |
| 订阅消息发送失败 | 写日志，保留失败状态，不标记成功 |
| 管理员权限不足 | 拒绝读取或修改管理数据 |
| 反馈已回复后被修改 | 云函数拒绝修改 |
| 数据库/网络异常 | 返回明确失败状态，前端不误报成功 |

## 10. 性能、隐私与安全

- 以云数据库条件查询和分页减少无效读取；列表只返回当前页面所需字段。
- 任务、随笔、反馈等所有用户数据查询必须限制在当前 openid 范围内。
- 管理员操作必须在云函数侧验证白名单。
- 云函数校验所有输入，采用字段白名单更新，防止客户端覆盖身份、创建时间、提醒状态等受控字段。
- 不在前端代码、日志或错误提示中输出密钥、完整敏感资料或内部堆栈。
- 图片访问遵循云存储权限设置；不得仅凭前端隐藏按钮来保护数据。
- 性能目标为常规列表与云函数操作尽可能在 1 秒内完成；通过真机/开发版测试记录实际耗时，不承诺所有网络条件下均达标。

## 11. 测试设计

### 11.1 单元/模块测试

- 登录：首次登录创建用户；再次登录不覆盖资料。
- 任务：增删改查、字段校验、置顶、四象限映射与排序、用户数据隔离。
- 提醒：未设置提醒、授权拒绝、提醒时间已过、时间修改、关闭提醒、发送成功/失败、并发扫描。
- 随笔：增删改查、默认标题、置顶与时间排序、用户数据隔离。
- 用户资料：允许字段更新、非法字段拒绝。
- 反馈：提交、未回复时修改、回复后拒绝修改。
- 管理员：白名单内外访问、反馈列表、回复操作权限。
- 图片：上传成功、上传失败、记录保存与图片 fileID 一致。

### 11.2 整体测试

1. 新用户登录并创建资料。
2. 创建含图片、不同四象限等级与提醒设置的任务，检查列表排序和详情。
3. 验证订阅授权及到点推送流程；同时验证失败日志与不重复处理策略。
4. 新建、编辑、置顶、删除随笔。
5. 修改个人资料并重启小程序验证持久化。
6. 提交反馈，以管理员身份回复，再以普通用户身份查看回复并确认不能修改。
7. 使用两个不同 openid 验证数据隔离。
8. 使用非管理员身份直接调用管理云函数，确认服务端拒绝。
9. 在弱网、云函数异常和图片上传失败时验证错误提示与数据一致性。

## 12. 开发顺序与完成标准

1. **基础框架与登录**：云环境配置、页面骨架、登录、用户初始化。
2. **任务模块**：任务 CRUD、四象限映射、排序、置顶与数据隔离。
3. **提醒模块**：订阅授权、定时触发器、发送日志与异常处理。
4. **随笔模块**：CRUD、图片、置顶与排序。
5. **我的模块**：资料、反馈、系统消息和作者邮箱。
6. **管理员反馈**：白名单鉴权、查看反馈、回复。
7. **回归测试与文档**：执行整体测试，检查权限、异常与性能。

MVP 验收条件：必做功能可运行；不同用户的数据互相隔离；非管理员无法调用管理功能；任务提醒遵守单任务单条的设计限制；用户反馈回复流程完整；主要异常均有可理解的提示；统计和手写功能不纳入本期验收。
