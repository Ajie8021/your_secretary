# 需求分析文档

## 一、项目概述

- **项目名称**：备忘秘书小程序
- **项目定位**：面向大学生的学业与校园事务 DDL 提醒工具。
- **核心价值**：在备忘录基础上加入微信订阅消息提醒，降低因忘记查看记录而错过 DDL 的概率。
- **项目性质**：个人练习项目，轻量、无广告，优先使用微信云开发降低服务器与运维成本。

## 二、目标用户

- **主要用户**：在校大学生。
- **典型场景**：课程作业、学生工作、活动申请、考试报名等有明确截止时间的事务。
- **用户特征**：日常高频使用微信，事务较为碎片化，容易遗忘截止时间。

## 三、功能需求

### 1. 登录

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1-1 | 使用微信小程序身份完成登录，取得可用于识别用户的 openid | 必做 |
| F1-2 | 首次登录时创建用户资料记录；再次登录时保留已有资料 | 必做 |
| F1-3 | 支持维护头像、昵称等个人资料；不得假定登录过程必然自动取得全部资料字段 | 必做 |

### 2. 用户端

#### （1）任务模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F2-1 | 展示任务名称、类型标签、内容摘要（文字/图片）、DDL | 必做 |
| F2-2 | 按置顶状态、时间管理四象限优先级和 DDL 排序 | 必做 |
| F2-3 | 长按任务置顶或取消置顶 | 必做 |
| F2-4 | 点击任务查看详情 | 必做 |
| F2-5 | 新建任务，名称默认为“无名”；类型支持内置类型与自定义文本 | 必做 |
| F2-6 | 任务重要程度使用四象限映射，选择 1–4 级并以颜色区分 | 必做 |
| F2-7 | DDL 与任务内容必填，内容可附图片 | 必做 |
| F2-8 | 可为任务设置一个提醒时间，并在保存时申请微信订阅消息授权 | 必做 |
| F2-9 | 支持编辑、删除任务 | 必做 |
| F2-10 | 修改提醒时间后更新提醒状态；关闭提醒后不得继续发送旧提醒 | 必做 |

四象限与等级映射如下，等级越高越优先：

| level | 象限 | 排序优先级 |
|---:|---|---:|
| 4 | 重要且紧急 | 最高 |
| 3 | 重要但不紧急 | 次高 |
| 2 | 紧急但不重要 | 次低 |
| 1 | 不重要且不紧急 | 最低 |

任务排序规则：置顶优先，其次 `level` 降序、`ddl` 升序，最后按创建时间降序作为稳定排序条件。

#### （2）随笔模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F3-1 | 展示随笔标题、正文摘要（两行/图片）和记录时间 | 必做 |
| F3-2 | 随笔列表按置顶优先、记录时间倒序排列 | 必做 |
| F3-3 | 长按随笔置顶或取消置顶 | 必做 |
| F3-4 | 点击随笔查看完整内容 | 必做 |
| F3-5 | 新建随笔，标题默认为“无题”，正文可附图片，自动记录创建时间 | 必做 |
| F3-6 | 支持编辑、删除随笔 | 必做 |

编辑随笔不改变其创建时间。

#### （3）我的模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F4-1 | 展示并允许修改头像、昵称、性别、出生日期、地址、职业 | 必做 |
| F4-2 | 用户可提交反馈；管理员回复前可修改，回复后置灰且服务端禁止修改 | 必做 |
| F4-3 | 提供系统消息入口；MVP 阶段用于查看管理员对反馈的回复及相关状态 | 必做 |
| F4-4 | 展示作者联系邮箱 | 必做 |

**系统消息范围说明：** MVP 不建设通用公告/广播系统；系统消息入口以反馈回复为主要内容。若后续需要管理员主动发布独立公告，再扩展消息集合与相关接口。

#### （4）图片

| 编号 | 需求 | 优先级 |
|---|---|---|
| F4-5 | 任务与随笔可选择并上传图片，保存云存储 fileID | 必做 |
| F4-6 | 上传失败时明确提示并允许重试，不得将本地临时路径当作持久图片地址保存 | 必做 |

本期仅支持图片，不支持视频、任意附件或手写。

### 3. 管理员端

| 编号 | 需求 | 优先级 |
|---|---|---|
| F5-1 | 复用微信身份，通过 `admins` 集合中的 openid 白名单鉴权 | 必做 |
| F5-2 | 管理员查看用户反馈并回复 | 必做 |
| F5-3 | 用户回复后不能再修改该条反馈；服务端必须校验此规则 | 必做 |
| F5-4 | 统计用户性别、年龄、地域、职业等群体信息 | 缓做 |

管理员权限必须在云函数端验证；前端隐藏管理员入口只用于界面体验，不能作为安全措施。

### 4. 拓展功能

| 编号 | 需求 | 优先级 |
|---|---|---|
| F6-1 | 手写功能 | 本期不做 |
| F6-2 | 独立公告/广播消息系统 | 本期不做 |

## 四、非功能需求

| 类别 | 要求 |
|---|---|
| 平台 | 微信小程序 |
| 主体与成本 | 个人主体；优先使用微信云开发，尽量避免自建服务器和额外运维成本 |
| 性能 | 列表加载流畅；常规云函数操作以 1 秒内响应为目标，实际表现需测试，不作为所有网络条件下的绝对保证 |
| 数据隔离 | 用户只能读取、修改自己的任务、随笔、资料和反馈 |
| 管理员鉴权 | 管理员操作必须由云函数检查 openid 白名单 |
| 提醒 | 每个任务最多发送一条订阅消息；实际送达受微信平台、模板、用户授权及接口结果影响 |
| 稳定性 | 对云函数调用、数据库操作、图片上传和消息发送失败提供明确反馈或日志 |
| 可维护性 | 代码按页面、云函数与业务模块组织；关键业务规则应有测试覆盖 |

## 五、技术约束

| 约束 | 说明 |
|---|---|
| 前端 | 微信原生小程序 + Vant Weapp |
| 后端 | 微信云开发：云函数、云数据库、云存储、定时触发器、订阅消息 |
| 身份识别 | 以云函数运行上下文取得的 openid 为准，不信任前端传入的用户标识 |
| 订阅消息 | 一次性订阅消息；用户拒绝授权时，任务仍可保存，但不启用提醒 |
| 定时任务 | 使用云函数定时触发器扫描到期提醒 |
| 数据访问 | 通过云函数实施输入校验、用户数据隔离和管理员权限校验 |
| 并发与失败 | 定时任务需尽量避免并发重复发送；发送成功后才标记已发送，失败记录日志。由于外部发送接口与数据库更新并非同一原子事务，不承诺严格的“恰好一次”投递 |

## 六、MVP 范围

**必做：**
- 微信身份识别与用户资料初始化；
- 任务增删改查、四象限排序、置顶；
- 单任务单条订阅消息提醒及基本失败处理；
- 随笔增删改查、置顶；
- “我的”基础资料、反馈、反馈回复消息入口、作者邮箱；
- 管理员白名单鉴权、反馈查看与回复；
- 图片上传与展示；
- 用户数据隔离与关键异常提示。

**缓做：**
- 管理员端用户群体统计。

**本期不做：**
- 手写；
- 独立公告/广播消息系统；
- 视频与其他附件上传。

## 七、技术栈

- **前端**：微信原生小程序 + Vant Weapp。
- **后端**：微信云开发（云函数 / 云数据库 / 云存储 / 定时触发器 / 订阅消息）。
- **用户鉴权**：云函数上下文 openid。
- **管理员鉴权**：`admins` 集合 openid 白名单。

## 八、验收标准

1. 新用户首次登录后创建资料，再次登录不覆盖已有资料。
2. 用户可完成任务和随笔的新增、查看、编辑、删除、置顶及取消置顶。
3. 任务四象限等级映射和排序符合本需求定义。
4. 用户可为任务设置一个提醒；拒绝订阅授权时仍可保存任务但不发送提醒。
5. 修改或关闭提醒后，不得按旧提醒设置继续发送。
6. 用户只能访问自己的任务、随笔、资料和反馈；通过不同 openid 验证隔离。
7. 非管理员直接调用管理云函数时，服务端拒绝访问。
8. 用户可提交反馈；管理员可回复；回复后用户无法再修改该反馈。
9. 图片上传失败、云函数失败及订阅消息发送失败均有正确的失败反馈或日志，不误报成功。
10. 用户统计与手写功能不纳入本期验收。
