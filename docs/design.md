# 设计文档

## 一、系统架构

```text
小程序端（原生 + Vant Weapp）
  ├─ 登录与全局状态
  ├─ 任务列表 / 任务编辑与详情
  ├─ 随笔列表 / 随笔编辑与详情
  ├─ 我的 / 基础资料 / 反馈 / 系统消息
  └─ 管理员端 / 反馈管理（统计缓做）
          │ wx.cloud.callFunction
          ▼
微信云开发
  ├─ 云函数：业务逻辑、权限校验、定时触发、订阅推送
  ├─ 云数据库：users / tasks / notes / admins / feedbacks
  ├─ 云存储：图片
  └─ 微信订阅消息
```

前端负责页面交互、表单基础校验、图片选择/上传和订阅授权申请；云函数负责身份识别、权限校验、业务规则、数据校验与数据库操作。不得仅依赖前端隐藏按钮保护数据或管理员功能。

## 二、设计约定

1. 用户身份以云函数运行上下文取得的 `OPENID` 为准，不信任客户端传入的 `_openid`。
2. `level` 使用整数 1–4 表示四象限，数值越大越优先：4 重要且紧急，3 重要但不紧急，2 紧急但不重要，1 不重要且不紧急。
3. 任务排序：`top` 降序、`level` 降序、`ddl` 升序、`createTime` 降序。
4. 随笔排序：`top` 降序、`createTime` 降序。
5. 默认任务名为“无名”，默认随笔标题为“无题”；`top` 默认 `false`，`reminded` 默认 `false`。
6. 用户拒绝订阅授权或不设置提醒时，任务仍可保存，但不建立有效的待发送提醒。
7. 每个任务最多发送一条提醒。只有发送接口确认成功后才将 `reminded` 设为 `true`；失败记录日志。
8. MVP 的系统消息入口主要展示管理员对用户反馈的回复，不建设独立公告/广播系统。
9. 用户统计为缓做功能；手写功能不纳入本期。

## 三、数据库设计

### 1. `users` 用户集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_openid` | string | 微信用户 openid；用户身份标识 |
| `avatar` | string | 头像地址或文件标识 |
| `nickname` | string | 昵称 |
| `gender` | string | 性别，默认“保密” |
| `birthday` | string | 出生日期，统一 `YYYY-MM-DD` |
| `address` | string | 用户填写的地址/地域信息 |
| `job` | string | 职业 |
| `createTime` | date | 首次创建时间 |

约束：首次登录按 openid 创建用户记录；再次登录不得覆盖已有资料。更新资料只允许修改头像、昵称、性别、生日、地址和职业等白名单字段，不允许修改 `_openid`、`createTime`。

### 2. `tasks` 任务集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 数据库生成的主键 |
| `_openid` | string | 所属用户，由云函数写入 |
| `name` | string | 任务名称，默认“无名” |
| `type` | string | 类型标签，可为内置或自定义文本 |
| `level` | number | 四象限等级，整数 1–4 |
| `ddl` | date | 截止时间，必填 |
| `content` | string | 任务内容，必填 |
| `images` | array | 云存储 fileID 列表，无图片时为空数组 |
| `top` | boolean | 是否置顶，默认 `false` |
| `remindAt` | date/null | 单个提醒时间；不提醒时为空 |
| `reminded` | boolean | 是否已成功发送，默认 `false` |
| `createTime` | date | 创建时间，编辑时不变 |

校验与更新规则：
- `level` 必须为 1–4 的整数；`ddl` 和 `content` 必填。
- 提醒时间必须是有效时间，且不得晚于任务 DDL；已过去的提醒时间应要求用户重新选择或关闭提醒。
- 所有查询、更新、删除和置顶操作均须同时校验任务 `_id` 与当前用户 openid。
- 修改提醒时间时重置 `reminded=false`；关闭提醒时清空 `remindAt`，避免旧提醒继续生效。
- 删除任务后，该任务不得继续被定时任务发送。

### 3. `notes` 随笔集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 数据库生成的主键 |
| `_openid` | string | 所属用户，由云函数写入 |
| `title` | string | 标题，默认“无题” |
| `content` | string | 正文 |
| `images` | array | 云存储 fileID 列表，无图片时为空数组 |
| `top` | boolean | 是否置顶，默认 `false` |
| `createTime` | date | 创建时间，编辑时不变 |

所有读写操作都要校验记录归属。编辑随笔不改变创建时间。

### 4. `admins` 管理员集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_openid` | string | 管理员 openid |
| `name` | string | 管理员备注名 |

管理员由维护白名单的方式授权，不提供普通用户自行提升权限的接口。每次管理操作均由云函数重新鉴权。

### 5. `feedbacks` 反馈集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 数据库生成的主键 |
| `_openid` | string | 提交用户，由云函数写入 |
| `content` | string | 反馈正文 |
| `reply` | string | 管理员回复；未回复时为空字符串 |
| `repliedAt` | date/null | 回复时间；未回复时为空 |
| `createTime` | date | 提交时间 |

规则：
- 用户只能查看自己的反馈。
- 用户只能修改尚未回复的反馈；回复后前端置灰，云函数必须拒绝修改。
- 管理员查看和回复反馈前必须通过白名单鉴权。
- 管理员回复时写入 `reply` 与 `repliedAt`。

### 6. 索引与分页

按实际查询创建必要索引：
- `tasks`：常用查询涉及 `_openid`、`top`、`level`、`ddl`、`createTime`；
- `notes`：常用查询涉及 `_openid`、`top`、`createTime`；
- `feedbacks`：`_openid`、`createTime`；
- `admins`、`users`：`_openid`。

具体组合索引以实际云数据库查询和控制台要求为准。列表应按需分页，避免一次性读取全部记录。

## 四、云函数设计

云函数建议统一返回结构：

```javascript
{ code: 0, message: "ok", data: {} }
```

失败时返回非零 `code` 和可理解的 `message`。异常细节记录在云函数日志中，不向前端返回堆栈或敏感信息。

| 云函数 | 职责 | 关键规则 |
|---|---|---|
| `login` | 登录与用户初始化 | 从云函数上下文获取 openid；首次创建用户，再次登录不覆盖资料 |
| `task` | 任务 CRUD、置顶 | 校验字段和记录归属；统一排序规则 |
| `note` | 随笔 CRUD、置顶 | 校验字段和记录归属；统一排序规则 |
| `user` | 用户资料读写 | 仅允许更新资料白名单字段 |
| `feedback` | 用户反馈提交、查询、修改 | 仅本人可操作；回复后禁止用户修改 |
| `admin` | 管理员鉴权、反馈列表与回复 | 每次管理操作检查 admins 白名单 |
| `sendReminder` | 定时扫描并发送任务提醒 | 校验提醒状态、发送订阅消息、记录成功状态与失败日志 |
| `stats` | 用户群体统计 | 缓做，本期不要求实现 |

### 1. `login`

- 输入：不依赖前端传入的身份标识。
- 处理：获取 openid，查询 `users`；不存在则创建默认资料。
- 输出：用户资料。
- 异常：无法取得 openid 或数据库读写失败时返回错误。

### 2. `task`

建议通过 `action` 区分操作：

| action | 输入 | 行为 |
|---|---|---|
| `list` | 分页参数（可选） | 查询当前用户任务并排序 |
| `detail` | `id` | 查询本人指定任务 |
| `create` | 任务字段 | 校验后创建；服务端写入 `_openid`、`createTime` 和默认状态 |
| `update` | `id`、允许修改的字段 | 校验归属与字段白名单后更新 |
| `delete` | `id` | 校验归属后删除 |
| `toggleTop` | `id` | 校验归属后切换置顶 |

排序：`top` 降序、`level` 降序、`ddl` 升序、`createTime` 降序。

### 3. `note`

| action | 输入 | 行为 |
|---|---|---|
| `list` | 分页参数（可选） | 查询本人随笔并排序 |
| `detail` | `id` | 查询本人指定随笔 |
| `create` | `title`、`content`、`images` | 校验后创建 |
| `update` | `id`、允许修改的字段 | 校验归属后更新 |
| `delete` | `id` | 校验归属后删除 |
| `toggleTop` | `id` | 校验归属后切换置顶 |

排序：`top` 降序、`createTime` 降序。

### 4. `user`

- `getProfile`：读取当前用户资料。
- `updateProfile`：只允许更新 `avatar`、`nickname`、`gender`、`birthday`、`address`、`job`。
- 禁止客户端修改 `_openid` 与 `createTime`。

### 5. `feedback`

- `listMine`：查询本人反馈，按创建时间倒序。
- `create`：校验正文后创建反馈，服务端写入 openid 与时间。
- `update`：仅允许修改本人且尚未回复的反馈。
- 忽略客户端传入的用户身份字段。

### 6. `admin`

- `check`：检查当前 openid 是否在 `admins` 集合。
- `listFeedbacks`：先鉴权，再分页查询反馈。
- `replyFeedback`：先鉴权，校验反馈 id 和回复内容，再写入 `reply`、`repliedAt`。
- 非管理员请求拒绝访问，不返回管理数据。

统计功能缓做。本期不实现 `stats` 云函数也不要求统计页面上线。

### 7. `sendReminder`

触发方式：云函数定时触发器，每分钟运行一次。

流程：
1. 获取当前时间。
2. 查询 `remindAt <= now` 且 `reminded=false` 的有效任务。
3. 再次确认提醒未被关闭、修改或随任务删除。
4. 调用微信订阅消息发送接口。
5. 发送接口确认成功后设置 `reminded=true`；失败记录任务标识、错误码与时间，不标记成功。
6. 单条任务失败不得阻断其他任务；设置合理批量上限，避免函数超时。

并发说明：定时触发器可能重叠执行，单纯查询 `reminded=false` 不能完全避免并发重复发送。实现时应使用可行的状态/锁机制或其他并发控制。发送接口与数据库更新并非同一原子事务，因此无法仅凭本地状态保证严格“恰好一次”；目标是尽量避免重复发送，并在确认发送成功后记录状态。

## 五、关键流程

### 1. 登录与用户初始化

```text
小程序启动
→ 调用 login 云函数
→ 云函数获取 openid
→ 查询 users
→ 已存在：返回现有资料
→ 不存在：创建默认资料并返回
→ 前端保存必要的登录状态
```

### 2. 新建任务与提醒

```text
填写任务名称、类型、level、DDL、正文与图片
→ 选择是否设置单个提醒时间
→ 前端校验表单与时间关系、上传图片
→ 若启用提醒，申请订阅消息授权
→ 用户拒绝授权：允许保存任务，但不启用提醒
→ 调用 task.create
→ 云函数重新校验并写入任务
→ 返回成功/失败结果
```

### 3. 修改或关闭提醒

```text
用户修改提醒时间或关闭提醒
→ 调用 task.update
→ 云函数校验任务归属与时间
→ 修改时间：更新 remindAt 并重置 reminded=false
→ 关闭提醒：清空 remindAt
→ 返回结果并刷新页面
```

### 4. 定时推送

```text
定时触发器（每分钟）
→ 查询到期且未成功发送的有效提醒
→ 逐条校验当前提醒状态
→ 调用订阅消息发送接口
→ 成功：reminded=true
→ 失败：记录日志，不标记成功
```

### 5. 管理员反馈回复

```text
管理员进入反馈管理页
→ 调用 admin 云函数
→ 云函数检查 openid 是否在 admins 白名单
→ 通过：返回反馈列表
→ 管理员回复
→ 写入 reply 与 repliedAt
→ 用户在反馈/系统消息页面查看回复
→ 该反馈不可再由用户修改
```

## 六、图片上传设计

1. 页面使用 `wx.chooseMedia` 选择图片。
2. 前端限制数量和大小，并展示上传状态。
3. 使用 `wx.cloud.uploadFile` 上传至云存储，取得 `fileID`。
4. 任务或随笔只保存 `fileID` 数组，不将本地临时路径当作持久数据。
5. 上传失败时提示并允许重试；数据库保存失败时不得提示成功。
6. 云文件清理应与记录删除策略保持一致，避免删除记录后遗留大量无用文件。

本期只支持图片。

## 七、页面结构

```text
pages/
├─ login/          登录与初始化
├─ task/           任务列表
├─ task-detail/    任务详情
├─ task-edit/      新建/编辑任务
├─ note/           随笔列表
├─ note-detail/    随笔详情
├─ note-edit/      新建/编辑随笔
├─ mine/           我的
│  ├─ profile/     基础资料
│  ├─ feedback/    用户反馈与回复

   └─ feedback/    管理员反馈管理
```

实际路由和目录名可根据项目实现调整，但页面职责与权限边界应保持一致。管理员统计页面属于缓做功能，本期不要求实现。

## 八、异常处理

| 场景 | 处理方式 |
|---|---|
| 登录/云函数调用失败 | 展示可理解的错误提示，允许重试 |
| 表单缺字段或格式错误 | 前后端校验，以云函数校验为准 |
| 记录不存在或不属于当前用户 | 拒绝访问，不泄露其他用户数据 |
| 图片上传失败 | 提示失败并允许重试，不保存临时路径 |
| 用户拒绝订阅授权 | 允许保存不带提醒的任务 |
| 提醒时间非法或已过期 | 要求重新选择或关闭提醒 |
| 订阅消息发送失败 | 记录日志，不标记为已发送 |
| 管理员权限不足 | 云函数拒绝读取或修改管理数据 |
| 反馈已回复后再次修改 | 云函数拒绝修改 |
| 数据库/网络异常 | 返回明确失败状态，前端不误报成功 |

## 九、性能、安全与隐私

- 列表采用条件查询与分页，避免不必要的全量读取。
- 用户任务、随笔、资料和反馈的读写必须限制在当前 openid 范围内。
- 管理员操作必须在云函数侧校验白名单。
- 更新数据使用字段白名单，防止客户端覆盖身份、创建时间和提醒状态等受控字段。
- 错误提示不暴露堆栈、密钥或敏感资料；日志仅记录排障所需信息。
- 图片访问权限遵循云存储配置，不能只靠隐藏页面入口保护资源。
- 常规云函数操作以 1 秒内响应为性能目标；通过实际测试记录结果，不保证所有网络与冷启动场景都达标。

## 十、测试设计

### 1. 模块测试

- 登录：首次创建用户；重复登录不覆盖资料。
- 任务：CRUD、字段校验、四象限映射、排序、置顶、用户隔离。
- 提醒：未设置提醒、授权拒绝、提醒时间已过、修改时间、关闭提醒、发送成功/失败及并发扫描。
- 随笔：CRUD、默认标题、置顶、排序、用户隔离。
- 用户资料：白名单字段可更新，受控字段不可修改。
- 反馈：提交、未回复时修改、回复后拒绝修改。
- 管理员：白名单内外访问、反馈列表、回复权限。
- 图片：上传成功/失败及 fileID 保存正确性。

### 2. 整体测试

1. 新用户登录并验证资料初始化与持久化。
2. 创建不同等级、含图片和提醒的任务，检查列表排序与详情。
3. 验证订阅授权、定时推送、发送失败日志和重复发送控制。
4. 完成随笔新增、编辑、置顶、删除。
5. 修改个人资料并重新进入小程序验证。
6. 提交反馈，管理员回复，用户查看回复并验证不可再修改。
7. 使用两个不同 openid 验证数据隔离。
8. 以非管理员身份直接调用管理云函数，验证服务端拒绝。
9. 模拟弱网、数据库异常与图片上传失败，验证提示和数据一致性。

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| 1 | 项目初始化、云环境、登录与用户初始化 | 首次创建资料，重复登录不覆盖资料 |
| 2 | 任务 CRUD、四象限排序、置顶 | 任务核心流程通过测试，用户数据隔离 |
| 3 | 订阅授权、定时提醒与失败处理 | 单任务单条设计生效，失败有日志 |
| 4 | 随笔 CRUD、置顶、图片 | 随笔流程与图片上传通过测试 |
| 5 | 我的：资料、反馈、系统消息入口 | 资料可修改，反馈流程可用 |
| 6 | 管理员反馈管理 | 白名单鉴权和回复流程通过测试 |
| 7 | 回归测试与文档整理 | 完成权限、异常、性能与整体测试 |

用户统计为缓做功能；手写和独立公告/广播消息系统不在本期范围内。
