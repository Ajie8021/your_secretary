# 项目总结报告

## 1. 项目概述

- **项目名称**：备忘秘书小程序
- **项目定位**：面向大学生的学业与校园事务 DDL 提醒工具
- **核心价值**：在备忘录基础上加入微信订阅消息提醒，降低因忘记查看而错过 DDL 的概率
- **项目性质**：个人练习项目，轻量、无广告，优先使用微信云开发降低服务器与运维成本
- **技术栈**：微信原生小程序 + Vant Weapp；后端为微信云开发（云函数、云数据库、云存储、定时触发器、订阅消息）

## 3. 架构与关键设计落地

| 设计约定                                         | 落地情况                                                     |
| ------------------------------------------------ | ------------------------------------------------------------ |
| 身份以云函数 `OPENID` 为准，不信任前端 `_openid` | 各云函数入口统一取 `getWXContext().OPENID`，未取得返回 401   |
| 统一响应结构 `{code,message,data}`               | 各云函数使用同一份 `response.js`（各目录各存一份，靠一致性单测防漂移） |
| 字段白名单更新                                   | 任务/随笔/资料/反馈更新均只接受明确字段，受控字段（`_openid`、`createTime`、`top`、`reminded`）不可被客户端覆盖 |
| 用户数据隔离                                     | 所有个人数据读写同时匹配 `_id` 与当前 openid；他人记录统一 404，不泄露存在性 |
| 管理员每次鉴权                                   | `admin` 云函数每个 action 先查 `admins` 白名单；前端入口隐藏仅作展示 |
| 提醒"每配置最多一次"                             | 修改提醒重置 `reminded`；关闭清空 `remindAt`；发送前重读最新记录；事务领取 + 锁机制防并发 |
| 图片只存 fileID                                  | 前端上传后提交 fileID 数组，失败项不入表单，不保存临时路径   |

**提醒并发机制说明**：采用事务领取任务、写 `reminderStatus=processing` 与 `reminderLockUntil` 锁、`reminderAttempts` 计数、失败退避 `reminderNextRetryAt`，满足"尽量避免重复发送"的设计目标。

## 5. 已知限制与风险

| 项                           | 说明                           | 影响                                       |
| ---------------------------- | ------------------------------ | ------------------------------------------ |
| 提醒不承诺严格恰好一次       | 外部发送接口与数据库更新非原子 | 极端情况下可能重复或漏发，已在设计文档声明 |
| 云文件清理未完全落地         | 删除记录后图片文件可能残留     | 存储成本缓慢增长，需后续清理任务           |
| 消息页 `pageSize` 取 50      | 消息量增大后一次读不全         | 后续需按 `replied` 过滤或独立消息接口      |
| 管理页与用户页样式两份       | 改动需同步                     | 维护成本，建议抽公共样式                   |
| 管理员白名单手工维护         | 误加/误删无审计                | 建议记录变更日志                           |
| 时间字段展示为 ISO 字符串    | 未做本地格式化                 | 可读性差，建议前端统一 `formatTime`        |
| `response.js` 各目录各存一份 | 依赖一致性单测防漂移           | 漏同步会被测试发现                         |

## 6. 开发过程中遇到的问题与处理

| 问题                                           | 根因                                                         | 处理                                                         |
| ---------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 图片上传报 `-503002 storage permission denied` | 云存储安全规则按 `cloudPath` 前缀白名单，`note-images/` 未放行 | 调整安全规则放行业务目录；路径保留扩展名与随机串             |
| 反馈提交首次返回 500                           | `feedbacks` 集合未建 / `utils.js` 未随云函数部署             | 建集合、云端安装依赖部署                                     |
| 反馈"取消/保存"按钮点击前白色、右侧溢出        | Vant 默认底色覆盖 + `gap`/`min-width` 导致超宽               | `custom-class` + `!important` 覆盖底色；按钮 `calc((100% - 16rpx)/2)` 等分、去 `gap` |
| 已登录账号编译直接进任务页                     | 启动页为 task、登录页仅兜底                                  | 符合设计；补 `ensureLogin` 失败跳登录页作为未登录兜底        |
| 提醒模块 `reminder-*` 未套统一响应             | 它们是内部纯逻辑，不直接对前端返回                           | 保持内部结构；统一的是 `sendReminder` 入口与各业务云函数     |

## 8. 后续任务

1. **云文件清理**：增加删除记录后的异步清理任务，或定期扫描孤儿文件。
2. **消息独立接口**：消息量增大后给 `feedback` 增加按 `replied` 过滤参数，替代放大 `pageSize`。
3. **白名单审计**：`admins` 变更记录日志（谁、何时、增删谁）。
4. **时间展示**：前端统一 `formatTime`，列表与详情不再直接显示 ISO 字符串。
5. **统计功能**：按缓做设计，后续以只读聚合云函数实现，不引入新集合。

---

## 9. 总结

项目按第 1–7 阶段完成 MVP 全部必做功能，核心权限边界（`OPENID` 隔离、管理员白名单、字段白名单）在云函数侧落地，提醒模块采用事务领取与锁机制尽量降低并发重复，图片仅持久化 fileID。各模块均有测试报告，回归清单已覆盖登录、任务、提醒、随笔、我的、管理员与异常边界。
